# Odontograma: Matriz Tecnica Final Por Pregunta

## Objetivo

Traducir el cuestionario clínico del odontograma a impactos técnicos concretos sobre tipos, store, persistencia, UI y reglas visuales del módulo actual.

## Convenciones de estado

| Estado                   | Significado                                                                                                    |
| ------------------------ | -------------------------------------------------------------------------------------------------------------- |
| Resuelta                 | El análisis actual ya permite planificar implementación sin otra decisión clínica.                             |
| Resuelta con dependencia | La dirección funcional está clara, pero depende de una decisión cercana para cerrar contrato o compatibilidad. |
| Bloqueada                | No debe implementarse comportamiento definitivo hasta cerrar la respuesta clínica.                             |

## Observaciones transversales

1. El cuello de botella principal no es el backend JSONB; es el contrato interno del frontend, que hoy reduce demasiados escenarios a un ClinicalEvent mínimo y a reglas visuales implícitas.
2. Las preguntas 7, 9, 11, 16, 24, 30, 31, 35, 36, 37, 38, 39 y 40 deben seguir tratándose como bloqueadores de implementación definitiva.
3. Las preguntas 18, 19, 23, 25, 26 y 27 justifican un contrato de diagnóstico de pieza de primera clase, no más notas parseadas dentro de eventos de endodoncia.
4. Las preguntas 1, 9, 10 y 11 no deberían resolverse tocando labels dispersos; necesitan una estrategia única de identidad de superficie y compatibilidad histórica.
